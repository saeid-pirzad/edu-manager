# کلاس‌یار

مدیریت آفلاین درس‌های یک دبیر، در یک سال تحصیلی، بدون backend یا وابستگی آنلاین زمان اجرا.

## اجرا و نصب

ورودی برنامه EduManager.html است؛ index.html به آن هدایت می‌کند. برای PWA، فایل‌های برنامه را با ساختار پوشه‌هایشان روی HTTPS، مانند GitHub Pages، قرار دهید. کپی‌کردن تنها HTML برای نسخهٔ فعلی کافی نیست.

بار اول با اینترنت باز کنید، تا نمایش «آماده اجرای آفلاین» صبر کنید و سپس نصب را بزنید. Chrome/Edge پیشنهاد نصب دارند؛ در Safari آیفون از Share → Add to Home Screen استفاده کنید. یک بار از آیکن نصب‌شده باز کنید و پس از قطع اینترنت دوباره اجرا را آزمایش کنید. نصب اولیه و دریافت نسخهٔ جدید به اینترنت نیاز دارند؛ کار روزمره از نسخهٔ ذخیره‌شده است. بازکردن مستقیم فایل با file:// فقط برای مشاهده و انتقال سوابق است.

## مسیر استفاده

مدرسه ← کلاس ← هنرجویان و درس‌ها ← برنامهٔ هفتگی ← جلسه، حضور و فعالیت ← نمرات امتحان ← گزارش.

در صفحهٔ اصلی، «برنامه امروز» زنگ‌ها را به‌ترتیب نشان می‌دهد؛ «شروع جلسه» مستقیم وارد ثبت همان زنگ می‌شود و «ادامه جلسه» سوابق موجود را باز می‌کند. روز و زنگ همچنان باید با برنامهٔ هفتگی منطبق باشند.

جلسهٔ قبلاً ثبت‌شده، حتی جلسهٔ امروز، ابتدا فقط برای مشاهده باز می‌شود. برای تغییر حضور، فعالیت، تاریخ یا واحد، «فعال‌کردن ویرایش» را بزنید؛ «پایان ویرایش» دوباره قفل می‌کند. بستن و بازکردن مجدد، مجوز ویرایش را نگه نمی‌دارد. جلسهٔ تازه‌ساخته‌شده برای ثبت اولیه باز است؛ جست‌وجو، مشاهده و کپی گزارش در حالت مشاهده نیز فعال‌اند.

زیر بنر خانه، «پیگیری حضور‌وغیاب» جلسه‌های ثبت‌نشده و حضورهای ناقص را از ابتدای سال تا دیروز نشان می‌دهد؛ مبنا برنامهٔ هفتگی فعلی و سوابق هر دو ترم است. هر مورد، ثبت/تکمیل حضور را باز می‌کند. زنگ بدون جلسهٔ واقعی را می‌توان «برگزار نشده» علامت زد؛ غیبت یا جلسهٔ ساختگی ایجاد نمی‌شود و انتخاب اشتباه از «برگزارنشده‌ها» قابل برگرداندن است. این تصمیم‌ها در پشتیبان کامل هم حفظ می‌شوند.

در حضور و غیاب، «باقی‌مانده‌ها حاضر» فقط وضعیت‌های تعیین‌نشده را ثبت می‌کند؛ غیبت، مرخصی و تأخیر قبلی حفظ می‌شوند. تغییر وضعیت همهٔ هنرجویان در گزینهٔ جداگانهٔ «تغییر همه» است. شمار حضورهای تعیین‌نشده و وضعیت ذخیره در همان پنجره دیده می‌شوند.

در فرم فعالیت، «ثبت فعالیت» هنرجو و نوع فعالیت را نگه می‌دارد؛ «ثبت و نفر بعد» پس از ذخیرهٔ موفق به هنرجوی بعدی می‌رود. مقدار و توضیح ثبت‌شده برای ورودی بعدی پاک می‌شوند و مثبت/منفی مقدار پیش‌فرض ۱ دارند. خطای ثبت یا تازه‌سازی همان جلسه، ورودی ناتمام را پاک نمی‌کند؛ ثبت تکراری هنگام ذخیرهٔ قبلی پذیرفته نمی‌شود.

ورود گروهی هنرجویان از CSV، در هر فایل تا ۵۰۰ ردیف غیرخالی و ۵ مگابایت می‌پذیرد. فایل بزرگ‌تر را به چند بخشِ مربوط به همان کلاس تقسیم کنید؛ فایل ردشده هیچ هنرجویی اضافه یا ویرایش نمی‌کند.

مدرسه، کلاس، هنرجو، درس و برنامهٔ هفتگی در دو نوبت همان سال مشترک‌اند. چهار مرحلهٔ دفتر نمره، میان‌ترم اول، پایان‌ترم اول، میان‌ترم دوم و پایان‌ترم دوم هستند. انتخاب مرحله، فضای ثبت روزمره را عوض نمی‌کند. سال‌های فایل‌های قدیمی در پشتیبان محفوظ‌اند؛ رابط معمول امکان مدیریت سال‌های دیگر ندارد.

کاردانش به‌طور پیش‌فرض عملی ۷۰٪ و نظری ۳۰٪ با حد قبولی ۱۴ است. نتیجهٔ سالانه فقط با کامل‌شدن چهار مرحله، میانگین برابر آن‌هاست. فنی پودمانی، نمرهٔ رسمی سالانه و واحدهای کار دارد؛ نمرهٔ جلسه و فعالیت، خودکار وارد امتحان رسمی نمی‌شود. صفر با ثبت‌نشده فرق دارد. جزئیات در [قرارداد بیزینس](docs/BUSINESS-RULES.md) است.

قبولی سالانهٔ کاردانش فقط به همین میانگین و حد قبولی سالانه وابسته است؛ شرط حداقل عملی یا نظریِ هر مرحله، شرط اضافهٔ قبولی سالانه نیست.

## داده، پشتیبان و بازیابی

بانک اصلی روی همان دستگاه و پروفایل مرورگر، در IndexedDB است. همگام‌سازی خودکار بین دستگاه‌ها نداریم. GitHub Pages فقط فایل‌های برنامه را میزبانی می‌کند.

تمام دکمه‌های پشتیبان، یک JSON کامل از همهٔ داده‌ها و نوبت‌ها می‌سازند. بازیابی عمومی پس از اعتبارسنجی، پیش‌نمایش و تأیید، **تمام اطلاعات فعلی را جایگزین می‌کند**؛ ورودی قدیمی نیز به همین مسیر تبدیل می‌شود. تکرار بازیابی همان فایل نوبت تازه ایجاد نمی‌کند. نسخهٔ ایمنی عملیات به‌صورت داخلی ساخته نمی‌شود؛ برای بازگردانی، فایل پشتیبان کاملِ قبلی لازم است.

نسخهٔ کامل داخلی هر ۲۰ دقیقه، هنگام باز و فعال‌بودن برنامه، جایگزین می‌شود. این نسخه در فضای همان مرورگر است؛ برای بازیابی پس از پاک‌شدن مرورگر باید فایل مستقل داشته باشید.

در مرورگر دارای File System Access می‌توانید با «انتخاب فایل و فعال‌سازی»، یک فایل JSON دستگاه را به پشتیبان خودکار وصل کنید. فعال‌سازی تنها پس از اولین نوشتن و بسته‌شدن موفق فایل تأیید می‌شود. تغییر ثبت‌شده پس از حدود ۲ ثانیه و سایر تغییرات هر ۳۰ ثانیه بررسی می‌شوند. رد مجوز، تغییر خارجی فایل یا خطای نوشتن، اتصال را متوقف و خطا را نمایش می‌دهد. «ذخیره اکنون / اجازه مجدد» برای درخواست اجازه و ذخیرهٔ تازه است. مرورگر فاقد این API، دریافت دستی پشتیبان کامل دارد. در برنامهٔ بسته، مرورگر معلق یا دستگاه خاموش نوشتن خودکار تضمین نمی‌شود.

پس از بازیابی کامل، اتصال فایل خودکار متوقف می‌ماند؛ حتی بازکردن دوبارهٔ برنامه فایل قبلی را جایگزین نمی‌کند. برای ادامه، «ذخیره اکنون / اجازه مجدد» را بزنید و جایگزینی فایلِ نام‌برده‌شده را تأیید کنید، یا فایل دیگری انتخاب کنید. کاهش شدید شمار داده‌ها نیز نوشتن خودکار را برای بررسی متوقف می‌کند. این محافظ، تضمین تشخیص همهٔ حذف‌های اشتباه یا جایگزینِ نگهداری یک کپی مستقل از فایل نیست.

رمز ورود، بانک یا پشتیبان را رمزگذاری نمی‌کند. فایل حاوی مشخصات و نمرات را در مخزن عمومی قرار ندهید. پشتیبان کامل با گزارش JSON یا XLSX تفاوت دارد.

جلسهٔ جدید و تغییر تاریخ یا زنگ جلسه باید با برنامهٔ هفتگی همان مدرسه، کلاس و درس منطبق باشد؛ روزهای فعال، تعداد زنگ‌ها و هفتهٔ فرد/زوج رعایت می‌شوند. فرم جلسه فقط زنگ‌های مجاز تاریخ انتخاب‌شده را نشان می‌دهد. سوابق قبلی و حضور و فعالیت آن‌ها قابل استفاده‌اند؛ تغییر برنامهٔ فعلی، جلسه‌های تاریخی را حذف نمی‌کند.

## گزارش‌ها

گزارش روزانه، هفتگی و ماهانه، جلسات **ترم انتخاب‌شده** را در بازه می‌خوانند؛ گزارش سالانه مهر تا شهریور هر دو ترم همان سال را پوشش می‌دهد. گزارش اولیا فقط برای هنرجوی انتخاب‌شده است. «کپی برای معاون»، چاپ/PDF، متن، JSON گزارش و XLSX در دسترس‌اند. کارتابل مستقل معاون در این شاخه وجود ندارد؛ کدهای اعتبارسنجی قدیمی فقط برای سازگاری فایل‌ها حفظ شده‌اند.

کارنامه برای هر هنرجو به‌صورت مستقل است: سطرها درس‌ها هستند و سرستون‌ها مراحل ارزشیابی. هر یک از چهار مرحلهٔ کاردانش، عملی، نظری و نتیجهٔ وزنی دارد. دروس عمومی و فنی پودمانی، ستون‌های متناسب با الگوی خود دارند. ستون و گزینهٔ نمرهٔ سالانه در جدول‌های کارنامه و چاپ نمایش داده نمی‌شود. پس از انتخاب کلاس، کارنامهٔ اولین هنرجوی فعال باز می‌شود؛ دکمه‌های قبلی و بعدی و انتخاب هنرجو، جابه‌جایی را با حفظ ترتیب ثبت ممکن می‌کنند. چاپ/PDF فقط کارنامهٔ کامل همان هنرجو را شامل می‌شود. در موبایل و تبلت، مرحلهٔ ارزشیابی یا پودمان را انتخاب می‌کنید تا فقط نمرات همان بخش کنار نام درس دیده شوند؛ انتخاب هنگام جابه‌جایی بین هنرجویان کلاس حفظ می‌شود. دسکتاپ و چاپ، جدول کامل همهٔ مراحل را نمایش می‌دهند.

در بخش کارنامه، «خروجی اکسل نمرات» یک فایل برای هنرجوی انتخاب‌شده یا کل کلاس می‌دهد. فایل همهٔ مراحل و پودمان‌های سال را با ترتیب ثبت، تفکیک فعال/بایگانی و سلول خالی برای نمرهٔ ثبت‌نشده شامل می‌شود؛ انتخاب مرحله در موبایل، محدودهٔ اکسل را محدود نمی‌کند. جدول و چاپ کارنامه همان نسخهٔ موجود هستند. برای ارسال نمرات، در همان پنجره حالت «ارسال در پیام‌رسان» را انتخاب کنید، سپس هنرجو یا کل کلاس را بزنید و بعد از آماده‌شدن XLSX، «انتخاب پیام‌رسان و ارسال» را بزنید. اگر ارسال فایل پشتیبانی نشود، «دریافت فایل برای پیوست» همان اکسل را برای ارسال دستی می‌دهد.

اکسل واقعی XLSX، کاملاً آفلاین، با چینش راست‌به‌چپ و تاریخ شمسی ساخته می‌شود. هر شیت فیلتر و مشخصات گزارش را دارد. نام فایل از نام دبیر و تاریخ‌وساعت شمسی تهیه گزارش به وقت تهران ساخته می‌شود. نام واردشدهٔ تنظیم‌کننده اولویت دارد؛ در نبود آن نام یکتای دبیر جلسات استفاده می‌شود. شیت خالی حذف می‌شود؛ گزارش خالی محدوده را خودکار گسترش نمی‌دهد. کد هنرجو متن، صفر مقدار عددی و نمرهٔ ثبت‌نشده سلول خالی است. فرمول، ماکرو یا پیوند خارجی ساخته نمی‌شود.

«اشتراک‌گذاری اکسل» فایل همین گزارش و فیلترهایش را آماده می‌کند؛ سپس با «انتخاب پیام‌رسان و ارسال» پنجرهٔ اشتراک دستگاه باز می‌شود. نمایش شاد یا سایر پیام‌رسان‌ها به دستگاه و برنامه‌های نصب‌شده بستگی دارد. در مرورگرهای فاقد پشتیبانی ارسال XLSX، «دریافت اکسل برای پیوست» را بزنید و فایل را در پیام‌رسان پیوست کنید. پسوند و محتوای اصلی اکسل حفظ می‌شود؛ لغو اشتراک دانلودی ایجاد نمی‌کند و تغییر اطلاعات یا محدودهٔ گزارش، آماده‌سازی دوباره می‌خواهد. تهیهٔ فایل آفلاین است؛ ارسال در پیام‌رسان به اتصال همان برنامه نیاز دارد.

## ساخت و بررسی پیش از انتشار

Node.js 22.13 یا بالاتر و برای آزمون مرورگر Edge/Chromium لازم است. می‌توانید مسیر مرورگر را با EDUMANAGER_EDGE تعیین کنید. ابزارهای توسعه در package-lock.json قفل‌اند؛ برنامهٔ نهایی dependency اجرایی ندارد.

```text
npm ci
npm run build
npm run dev
npm run check:release
npm run release:package
```

npm run dev برای توسعه، برنامه را روی http://127.0.0.1:4173/ اجرا می‌کند؛ کاربر نصب‌شده نیازی به اجرای این دستور ندارد. برای تغییرات، src/ را ویرایش کنید؛ خروجی assets/ را دستی تغییر ندهید. ساخت، بسته‌ها، نگاشت‌های دیباگ، فهرست cache و شناسهٔ انتشار worker را تولید می‌کند. npm run build:check همگامی آن‌ها را بدون نوشتن بررسی می‌کند.

خروجی آمادهٔ میزبانی با npm run release:package در dist ساخته می‌شود و فقط فایل‌های خود برنامه را دارد. فایل‌های واقعی مدرسه در docs/School-doc در Git رهگیری شده‌اند؛ انتشار ریشهٔ مخزن یا عمومی‌بودن خود مخزن، این داده‌ها را با بسته‌بندی dist محافظت نمی‌کند. پیش از انتشار، دادهٔ مدرسه و تاریخچهٔ Git باید جدا تعیین تکلیف شوند. فایل‌های اصلی در این ممیزی حذف نشده‌اند.

برای حفظ نشانی و هویت نصب قبلی، محتوای dist باید در همان مسیر فعلی سایت قرار بگیرد؛ پوشهٔ تازه با نشانی /dist یک مسیر نصب متفاوت می‌سازد. تولید این پوشه به‌تنهایی چیزی منتشر نمی‌کند.

دروازهٔ انتشار شامل قالب‌بندی، lint، آزمون واحد، قرارداد بانک و دارایی‌های آفلاین، گردش‌کار مرورگر و ارتقای PWA، حذف امن، دفتر نمرهٔ موبایل و بازیابی سال است. CI همین فرمان را اجرا می‌کند. داده و پروفایل واقعی کاربر وارد آزمون نمی‌شوند. موفقیت خودکار جای آزمون نصب، کیبورد و فایل روی Android و iPhone واقعی را نمی‌گیرد.

آزمون `npm run test:annual-backup`، دانلود واقعی فایل کامل، بازیابی دو نوبت یک سال،
تکرار بازیابی و بازکردن آفلاین را با ۱۰۰ هنرجو و ۵۱۲ جلسهٔ مصنوعی بررسی می‌کند.
این آزمون در `npm run check:release` و CI نیز با پروفایل موقت جداگانه اجرا می‌شود.

رنگ‌های مشترک رابط در `src/styles/product-tokens.css` تعریف شده‌اند و از پالت
Reactium استفاده می‌کنند. `npm run test:theme` نماهای موبایل، تبلت و دسکتاپ را
با دادهٔ ساختگی ثبت و کنتراست و عرض صفحه را بررسی می‌کند؛ این آزمون نیز در
دروازهٔ انتشار اجرا می‌شود. گزارش و تصاویر آن در مسیر موقت چاپ‌شده باقی می‌مانند.

لوگوی اصلی `assets/logo3.png` است و در هدر، ورود، معرفی و پنجرهٔ نصب استفاده
می‌شود. آیکن‌های نصب ۱۹۲ و ۵۱۲، آیکن اپل ۱۸۰ و favicon اندازهٔ ۳۲ در
`assets/icons/` با پیشوند `app-cream-v2-` هستند؛ زمینهٔ مات کرم `#FFFAED` با لوگوی قرمز هماهنگ است. آیکن معمولی دسکتاپ لوگوی بزرگ‌تر دارد؛ آیکن `maskable` موبایل جداگانه با حاشیهٔ امن ساخته می‌شود. اصل تصویر
تغییر نمی‌کند. برای تولید دوبارهٔ اندازه‌ها در Windows، فرمان
`powershell -NoProfile -File scripts/generate-brand-icons.ps1` و سپس
`npm run build` را اجرا کنید. `npm run test:logo` نمایش لوگو و بایت‌های تصاویر
در اجرای آنلاین و آفلاین را با پروفایل آزمایشی بررسی می‌کند و در دروازهٔ انتشار
نیز اجرا می‌شود.

برای آیکن نصب قبلی، تغییر بایت PNG با آدرس ثابت کافی نیست؛ نام فایل‌های آیکن نسخه‌دار شده ولی `id`، نشانی manifest و مسیر نصب تغییر نکرده‌اند. پس از انتشار، برنامه را آنلاین باز کنید، به‌روزرسانی را بگیرید و پنجره‌های برنامه را ببندید و دوباره باز کنید. در Chrome جدید اگر گزینهٔ **Review app update** در منوی سه‌نقطه ظاهر شد، تغییر آیکن را تأیید کنید. پاک‌کردن دادهٔ سایت یا پروفایل مرورگر برای تعویض آیکن لازم نیست و می‌تواند دادهٔ آموزشی را حذف کند. [توضیح رسمی Chrome دربارهٔ تغییر آیکن](https://developer.chrome.com/blog/improvements-to-web-app-updates).

### انتشار کنترل‌شده در GitHub Pages

گردش‌کار [.github/workflows/ci.yml](.github/workflows/ci.yml) با نام «Verify and deploy EduManager»، ابتدا روی Windows تمام بررسی‌های `npm run check:release` و سپس بسته‌بندی را اجرا می‌کند. فقط پس از موفقیت هر دو مرحله، محتوای `dist` به‌عنوان بستهٔ Pages ارسال می‌شود؛ job جداگانهٔ `deploy` به موفقیت `verify` وابسته است.

انتشار فقط برای مخزن `saeid-pirzad/edu-manager` و شاخهٔ `master` فعال است. Pull Requestها و شاخه‌های دیگر بررسی می‌شوند و اجازهٔ ارسال یا انتشار بسته ندارند. دسترسی نوشتن Pages و توکن OIDC فقط به job انتشار داده می‌شود. اجرای درحال‌انجام master برای انتشار جدید لغو نمی‌شود.

تنظیم یک‌بارهٔ مخزن در GitHub: **Settings → Pages → Build and deployment → Source → GitHub Actions**. این گزینه باید پیش از اولین Push گردش‌کار جدید فعال باشد تا انتشار قدیمی از ریشهٔ master ادامه پیدا نکند. ساختار، مجوزها و محیط `github-pages` مطابق [راهنمای رسمی GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) است؛ توکن شخصی در فایل گردش‌کار قرار نمی‌گیرد.

پس از Push روی master، در تب **Actions** وضعیت `verify` و سپس `deploy` را دنبال کنید. شکست آزمون یا بسته‌بندی، انتشار همان اجرا را متوقف می‌کند. نشانی برنامه همان **https://saeid-pirzad.github.io/edu-manager/** است؛ نام پوشهٔ `dist` وارد نشانی عمومی نمی‌شود و هویت نصب فعلی PWA حفظ می‌شود.

در اجرای ناموفق، اگر آزمون خروجی تشخیصی تولید کرده باشد، بخش Artifacts فایل `audit-failure-<run>-<attempt>` را تا سه روز نگه می‌دارد: فقط نتیجه‌های JSON و PDF/تصاویر مصنوعیِ مسیرهای مجاز آزمون‌ها، نه پروفایل مرورگر، فایل پشتیبان واقعی یا فایل‌های مدرسه. این خروجی برای تشخیص خطا است و شکست آزمون را به موفقیت یا انتشار تبدیل نمی‌کند.
