# edu-manager

برنامه شخصی مدیریت کلاس و نمرات؛ آفلاین، بدون بک‌اند و با خروجی محلی JSON و TXT.

## فایل‌ها

- `EduManager.html`: پوسته و نقطهٔ ورود برنامه؛ فایل‌های CSS و JavaScript را با ترتیب مشخص بارگذاری می‌کند.
- `src/`: کد منبع تفکیک‌شده؛ راهنما در `src/README.md` و ترتیب ساخت در `source-map.json` است.
- `assets/scripts/` و `assets/styles/`: خروجی ساخت برای انتشار؛ مستقیم ویرایش نشوند.
- `scripts/`: ساخت، کنترل کیفیت، سنجش کارایی و اجرای محلی.
- `audit/`: آزمون‌های واحد و مرورگر؛ راهنمای اجرا در `audit/README.md` است.
- برای اجرا، پوشهٔ کامل پروژه لازم است؛ جابه‌جایی تنها فایل HTML کافی نیست.
- `app.webmanifest` و `service-worker.js`: فایل‌های فنی نصب و اجرای آفلاین PWA.
- `index.html`: ورودی کوچک GitHub Pages؛ فقط به فایل اصلی هدایت می‌کند و کد برنامه را تکرار نمی‌کند.

## GitHub Pages

پس از بررسی و ارسال تغییرات توسط مالک، در Settings → Pages:
Source = Deploy from a branch، Branch = master، Folder = /(root).
نشانی مورد انتظار: https://saeid-pirzad.github.io/edu-manager/
فعال‌بودن لینک باید بعد از انتشار بررسی شود.

## نصب

لینک را بار اول با اینترنت باز کنید؛ تا نمایش «آماده اجرای آفلاین» صبر کنید.
در Chrome/Edge از نصب برنامه و در Safari آیفون از Share → Add to Home Screen استفاده کنید.
یک بار از آیکن نصب‌شده باز کنید و سپس قطع اینترنت را امتحان کنید.
نصب اولیه، نصب مجدد و به‌روزرسانی به اینترنت نیاز دارند؛ اجرای روزمره از نسخه ذخیره‌شده است.

## داده‌ها

اطلاعات روی همان دستگاه و پروفایل مرورگر است؛ همگام‌سازی خودکار نداریم.
پشتیبان JSON را منظم ذخیره کنید. فایل‌های نمره و پشتیبان را به مخزن عمومی نفرستید.
نسخه محلی فایل و نسخه GitHub Pages محل ذخیره جدا دارند؛ انتقال با پشتیبان و بازیابی است.

## به‌روزرسانی

پس از تغییر کد منبع، HTML یا manifest، دستور `npm run build` و سپس `npm test` را اجرا کنید.
ساخت، فایل‌های انتشار و فهرست cache را تولید می‌کند و VERSION سرویس‌ورکر را از کل فایل‌های انتشار محاسبه می‌کند.
نسخه جدید فقط پس از دریافت کامل آماده می‌شود. پیش از اعمال آن، ویرایش‌های معتبر پنجره فعلی ذخیره می‌شوند؛ فقط همین پنجره بازخوانی می‌شود. پنجره‌های دیگر خودکار بازخوانی نمی‌شوند.

## فونت آفلاین

فونت IRANSans در سه وزن معمولی، متوسط و ضخیم داخل assets/styles/app.css جاسازی شده و هیچ CDN یا دانلود زمان اجرا ندارد.

## توسعهٔ محلی

Node.js 22.13 یا بالاتر لازم است. ساخت و تست واحد بدون dependency اجرایی‌اند؛ برای قالب‌بندی و lint، ابزارهای توسعه را با `npm ci` نصب کنید.

```text
npm ci
npm run build
npm run dev
npm run check
```

`npm run dev` برنامه را روی `http://127.0.0.1:4173/` اجرا می‌کند.
برای تست مرورگر، Edge یا مرورگر Chromium معرفی‌شده در `EDUMANAGER_EDGE` لازم است.
`npm run build:check` بدون نوشتن فایل بررسی می‌کند که خروجی انتشار با منبع همگام است.

`npm run check` قالب‌بندی، ESLint، ساخت و تمام تست‌ها را اجرا می‌کند. برای یکسان‌سازی
قالب `npm run format` و سپس `npm run build` را اجرا کنید. `npm run bench` سنجش
برنامهٔ ذخیره با ۱۰۰۰، ۱۰۰۰۰ و ۵۰۰۰۰ رکورد است؛ جای سنجش رابط روی گوشی را نمی‌گیرد.
رویدادهای HTML به توابع جدا منتقل شده‌اند؛ CSP اجرای اسکریپت inline را ممنوع می‌کند.

## پشتیبان کامل و گزارش‌ها

از «پشتیبان‌ها» می‌توان خروجی همین دوره یا پشتیبان کامل همه دوره‌ها را گرفت. پشتیبان کامل شامل دوره‌ها، تاریخچه، بازگردانی، کارنامه‌های ثابت و پشتیبان‌های داخلی است. بازیابی کامل، دوره‌ها را با شناسه مستقل اضافه می‌کند و اطلاعات فعلی را بازنویسی نمی‌کند.
پشتیبان کامل داخلی هر ۲۰ دقیقه در زمان باز و فعال بودن برنامه جایگزین می‌شود. مرورگر در پس‌زمینه یا هنگام بسته بودن برنامه اجرای زمان‌بندی را تضمین نمی‌کند. این نسخه در همان فضای برنامه است؛ فایل مستقل را جدا نگه دارید.
توضیحات گزارش برای هر دوره جدا روی دستگاه ذخیره و در پشتیبان کامل درج می‌شوند. پس از تغییر داده، پیش‌نمایش قبلی معتبر نیست و باید دوباره تهیه شود. میانگین نمایش‌داده‌شده میانگین ساده دروس است، نه معدل رسمی با ضرایب.

## میز کار روزانه و دسترس‌پذیری

داشبورد، جلسات امروز و برنامه هفتگی را کنار حضور‌وغیاب تعیین‌نشده، نمرات ناتمام و موارد نیازمند جبران نشان می‌دهد. شمار نمرات بر مبنای هنرجویان فعال و هر درس است؛ جلسات ثبت‌نشده غیبت محسوب نمی‌شوند. پس از تغییر تاریخ روز، اقدام‌های جلسه از میز کار قدیمی جلوگیری و صفحه تازه می‌شود.
پنجره‌ها فوکوس صفحه‌کلید را داخل خود نگه می‌دارند و پس از بسته‌شدن به کنترل قبلی برمی‌گردانند. تقویم شمسی با Enter، Space یا کلید پایین باز می‌شود؛ Escape ابتدا تقویم و سپس پنجره را می‌بندد. تاریخ غیرفعال از فیلد نمایشی قابل تغییر نیست. منوهای بیشتر با کلیک بیرون یا Escape بسته می‌شوند.

## ایمنی نمرات و بازیابی

نمرات موقت کاردانش و پودمانی، علاوه بر نسخه محلی، در IndexedDB ذخیره می‌شوند. ارتقای پایگاه فیزیکی از نسخه ۱ به ۲، مخزن پیش‌نویس‌ها را بدون حذف داده‌های قبلی اضافه می‌کند. اگر داده‌های دوره بعد از ایجاد پیش‌نویس تغییر کرده باشند، بازیابی آن به بازبینی و تأیید نیاز دارد. پیش‌نویس نشست دیگر پس از پذیرش دوباره پیشنهاد نمی‌شود.

پشتیبان کامل با قالب نسخه ۲، پیش‌نویس‌های باقی‌مانده نشست‌های دیگر را هم نگه می‌دارد. نسخه ۱ همچنان قابل بازیابی است. پیش‌نویس واردشده بدون تأیید روی نمره نهایی اعمال نمی‌شود. بازیابی دوره‌ها و پیش‌نویس‌ها یک تراکنش واحد است؛ خطا نباید واردکردن ناقص ایجاد کند.

گزارش مدیریت به‌صورت پیش‌فرض جزئیات خلاصه دارد: آمار همه هنرجویان حفظ می‌شود و جزئیات هر جلسه، هنرجویان دارای فعالیت یا نمره را نشان می‌دهد. حالت کامل برای نمایش همه افراد هر جلسه در دسترس است. JSON اطلاعات کامل افراد در محدوده انتخاب‌شده را نگه می‌دارد؛ گزارش اولیا فقط اطلاعات هنرجوی انتخاب‌شده را ارائه می‌کند.

در محیط آزمایشی، خطای کمبود فضا، لغو تراکنش، توقف اجباری مرورگر، تعارض دو تب، ارتقای پایگاه قدیمی، بازیابی در پروفایل جدا و چاپ چندصفحه‌ای بررسی شده‌اند. آزمون روی دستگاه واقعی Android و iPhone همچنان لازم است.

## کار با موبایل و دریافت فایل

خروجی‌های JSON، TXT و CSV از مسیر مشترک دریافت فایل استفاده می‌کنند؛ لینک دانلود به صفحه متصل و پس از فرصت دریافت، آزاد می‌شود. وضعیت «درخواست دانلود» به معنی تأیید ذخیره روی دستگاه نیست؛ فایل را در پوشه دانلودها بررسی کنید.

پنجره‌ها ارتفاع و جابه‌جایی محدوده قابل‌دیدن صفحه را دنبال می‌کنند تا هنگام باز شدن کیبورد، محتوای فرم و دکمه ذخیره قابل دسترس بمانند. ارتفاع اضافی فیلدهای عمودی و چهار انتخابگر معیوب CSS موبایل اصلاح شده‌اند.

دریافت واقعی هفت فایل شامل پشتیبان کامل، پشتیبان دوره، قالب CSV و گزارش مدیریت و اولیا در دو قالب JSON/TXT در Chromium آزمایش شد. بازیابی همان فایل دانلودشده و انتخاب مجدد یک فایل نیز موفق بود. کوچک‌شدن مستقل محدوده دید و جابه‌جایی آن به‌صورت شبیه‌سازی بررسی شده است؛ رفتار کیبورد و دانلود/اشتراک‌گذاری سیستم‌عامل روی گوشی واقعی هنوز باید بررسی شود.

## ویرایش مشخصات مدرسه، کلاس و درس

در فهرست مدرسه‌ها و کلاس‌ها، از منوی «بیشتر ← ویرایش مشخصات» استفاده کنید؛ داخل صفحه مدرسه و کلاس نیز دکمه مستقیم ویرایش وجود دارد. نام در دوره جاری اصلاح می‌شود و شناسه، هنرجویان، نمرات، جلسات و برنامه هفتگی حفظ می‌شوند. نام تکراری مدرسه و نام تکراری کلاس در یک مدرسه پذیرفته نمی‌شود. تغییر نام در تاریخچه ثبت و از همان بخش قابل بازگردانی است.

در «تنظیمات درس»، نام، دبیر، زنگ هفتگی و مشخصات توصیفی قابل اصلاح‌اند. پس از ثبت نمره، روش ارزشیابی، حدنصاب‌ها و ساختار دارای سابقه حفظ می‌شوند؛ اصلاح کد، رشته، پایه یا متولی در شناسنامه توصیفی، نسخه قواعد و محاسبه قبلی را تغییر نمی‌دهد. بخش قواعد و ساختار در ویرایش درس جمع‌شده است و برای تعریف درس جدید باز می‌شود. تغییر تعداد زنگ هفتگی، جای جلسات برنامه هفتگی را خودکار تغییر نمی‌دهد.

فرم‌ها خطای ذخیره را نمایش می‌دهند و ورودی را برای تلاش دوباره نگه می‌دارند. بستن فرم دارای تغییرات ذخیره‌نشده نیاز به تأیید دارد. ذخیره فرم قدیمی پس از تغییر دوره یا نسخه اطلاعات رد می‌شود و دوره بسته قابل ویرایش نیست.

جایگزینی فرم ویرایش با پنجره‌ای دیگر هم از تغییرات ذخیره‌نشده محافظت می‌کند. با لغو جایگزینی، متن فرم و مقصد ذخیره قبلی حفظ می‌شوند؛ فرم در حال ذخیره جایگزین نمی‌شود.
خطای عددی با عنوان فارسی فیلد نمایش داده می‌شود و فیلد نامعتبر مشخص و فوکوس می‌شود؛ اگر داخل بخش بسته باشد، همان بخش باز می‌شود. نام مدرسه و کلاس در سربرگ تنظیمات درس نمایش داده می‌شوند. باز شدن فرم نیز به همان کلاس و دوره درخواست‌شده محدود است و درس حذف‌شده به تعریف جدید تبدیل نمی‌شود.

مشخصات توصیفی درس از یک مسیر مشترک خوانده می‌شوند؛ شناسنامه ناقص، بقیه مقادیر را از قواعد ثبت‌شده می‌گیرد. کپی تعریف درس، آخرین پایه، رشته، کد و متولی اصلاح‌شده را حفظ می‌کند، نمره‌ای منتقل نمی‌کند و نیازمند تأیید قواعد است. در دوره جدید نیز شناسنامه فعلی منتقل می‌شود؛ اگر با شناسنامه نسخه قواعد تفاوت داشته باشد، نسخه جدید باید بررسی و تأیید شود. با تغییر سال، مرجع ابلاغیه سال قبلی پاک می‌شود. این کار نسخه قواعد و نمرات دوره مبدأ را تغییر نمی‌دهد.
کارنامه ثابت جدید، شناسنامه توصیفی زمان صدور را جدا از نسخه قواعد محاسبه نگه می‌دارد. اصلاحات بعدی نام‌ها در گزارش‌های جاری و برنامه هفتگی دیده می‌شوند؛ کارنامه‌های ثابت قبلی بازنویسی نمی‌شوند.

در فرم ویرایش مدرسه، کلاس و درس، وضعیت تغییرات ذخیره‌نشده و بخش «بازبینی تغییر پیش از ذخیره» به‌صورت زنده نمایش داده می‌شوند. مقدار قبلی و جدید هر فیلد قابل مقایسه است؛ «بازگردانی مقادیر فرم» فقط ورودی‌های فرم را به زمان باز شدن آن برمی‌گرداند و هیچ داده ذخیره‌شده‌ای را تغییر نمی‌دهد.
افزودن مدرسه و کلاس نیز نام خالی، بیش از ۵۰۰ نویسه و نام تکراری را بررسی می‌کند؛ مقایسه نام، تفاوت ک/ك و ی/ي را یکسان می‌گیرد. خطای ذخیره نباید نام واردشده را پاک کند. ثبت هم‌زمان و تغییر مدرسه یا دوره در فاصله انتظار ثبت، کنترل می‌شوند. نام‌های تکراری باقی‌مانده از نسخه‌های قدیمی، مانع اصلاح سایر مشخصات همان رکورد نمی‌شوند.

در درس پودمانی، بخش «نام پودمان‌ها و واحدهای یادگیری» از قواعد محاسبه جداست. از «بیشتر ← ویرایش نام پودمان‌ها» هم می‌توان مستقیم وارد آن شد. حتی پس از ثبت نمره، اصلاح عنوان مجاز است؛ شناسه، نمره، تعداد واحدها، ارتباط جلسات و نسخه قواعد حفظ می‌شوند. نام خالی یا عنوان تکراری جدید در همان محدوده پذیرفته نمی‌شود؛ نام واحد می‌تواند در پودمان‌های متفاوت یکسان باشد. بازبینی تغییرات، بازگردانی فرم، تاریخچه و بازگردانی ثبت نیز برای عنوان‌ها کار می‌کنند.
گزارش جاری عنوان اصلاح‌شده را می‌خواند؛ کارنامه ثابت قبلی بازنویسی نمی‌شود. در دوره بسته یا وضعیت مسدود، فرم درس فقط خواندنی و فیلدهای آن غیرفعال‌اند؛ دکمه انصراف همچنان فعال است. تعداد واحدهای درس فاقد نمره همچنان از بخش قواعد قابل تنظیم است؛ محدودیت تغییر ساختار درس دارای جلسه حفظ می‌شود.

## محدوده گزارش و عنوان دوره

ورود به گزارش از صفحه مدرسه یا کلاس، همان محدوده را برای گزارش روزانه و هفتگی انتخاب می‌کند؛ ورود به محدوده جدید، مخاطب را روی مدیریت، هنرجو را خالی و تاریخ را روی امروز می‌گذارد. هنگام تعویض دوره نیز فیلتر هنرجو و مخاطب قبلی پاک می‌شود. توضیحات گزارش همچنان برای هر دوره و محدوده جدا نگه داشته می‌شوند.

در «اصلاح عنوان دوره»، عنوان نوبت قابل ویرایش است و سال فقط نمایش داده می‌شود؛ برای سال دیگر باید دوره مستقل ساخت. فرم، بازبینی تغییرات و نگهداری ورودی پس از خطا دارد. کنترل عنوان تکراری در تراکنش پایگاه انجام می‌شود تا دو پنجره هم‌زمان نتوانند دو دوره را به یک سال/عنوان تغییر دهند. بازگردانی عنوان نیز نمی‌تواند عنوان متعلق به دوره دیگر را تصاحب کند.

ساخت دوره، عنوان فهرست و عنوان داخل داده را یکسان ثبت می‌کند. بازیابی، برای عنوان هم‌نام یک عنوان متمایز با حداکثر ۶۰ نویسه می‌سازد؛ برخورد عنوان‌ها داخل همان فایل نیز بررسی می‌شود. در بازگردانیِ ویرایش معمول پس از بازیابی، عنوان اختصاصی دوره بازیابی‌شده حفظ می‌شود؛ تغییر عنوانی که واقعاً در تاریخچه انجام شده، همچنان تابع کنترل تکراری بودن است.

حذف مدرسه، کلاس و درس اکنون اثر حذف را نمایش می‌دهد و به واردکردن نام دقیق و ذخیره موفق پشتیبان داخلی پیش از حذف نیاز دارد. تغییر دوره یا اطلاعات پس از بازشدن فرم، عملیات را متوقف می‌کند. پشتیبان داخلی از بخش پشتیبان‌ها و آخرین تغییر از تاریخچه قابل بازگردانی است؛ پشتیبان داخلی محدود به حافظه مرورگر و سیاست نگهداری موجود است و جای خروجی فایل مستقل را نمی‌گیرد.

`EduManager-data.json` در پوشه دلخواه دستگاه انتخاب کنید. همه دوره‌ها، داده‌ها و
پیش‌نویس‌های قابل بازیابی در همان فایل نوشته می‌شوند؛ افزودن، ویرایش و حذف در
برنامه، نسخه جدید همان فایل را جایگزین می‌کند. بانک مرورگر همچنان محل کار برنامه
است و فایل انتخابی یک پشتیبان کامل مستقل است، نه بانک زنده قابل ویرایش با ویرایشگر متن.

این قابلیت به File System Access در Chrome/Edge دسکتاپ و اجازه کاربر نیاز دارد.
تغییرات ثبت‌شده پس از حدود ۲ ثانیه و سایر تغییرات هر ۳۰ ثانیه بررسی می‌شوند؛ در
صفحه بسته، سیستم خاموش یا مرورگر معلق، نوشتن خودکار تضمین نمی‌شود. قبل از خروج،
«ذخیره اکنون / اجازه مجدد» را بزنید و پیام «ذخیره شد» را بررسی کنید. ممکن است پس از
بازگشایی مرورگر اجازه مجدد لازم باشد. مرورگرهای فاقد این API فقط پشتیبان دستی دارند.

فایل انتخاب‌شده با پاک‌سازی کامل داده‌های مرورگر حذف یا خالی نمی‌شود. برای بازیابی
از «بازیابی از فایل» استفاده کنید. تغییر فایل توسط برنامه دیگر، نوشتن خودکار را
متوقف می‌کند تا بدون تأیید بازنویسی نشود. اطلاعات شخصی فایل رمزنگاری نمی‌شوند؛ آن
را در پوشه امن نگه دارید و در Git منتشر نکنید (نام پیش‌فرض در ریشه پروژه ignore
شده است). خرابی دیسک همچنان می‌تواند فایل همان دستگاه را از بین ببرد.
