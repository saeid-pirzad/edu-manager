# Stylesheet ownership and cascade

Edit the source styles here. `assets/styles/` is generated by `npm run build`.
`source-map.json` is the single list of source inclusion and cascade order; the
order is deliberate and must not be alphabetized.

The page loads `app.css` first and `daily-workflow.css` second. Both bundles are
still loaded as two local files, including when offline. Source decomposition
does not introduce network imports, runtime loaders, cascade layers or a new
specificity model.

Some features intentionally appear in both phases. Their earlier files define
the feature, while the later `workflow/` files integrate it with shared work
areas. Those files keep their exact original positions so print rules, media
conditions, fallbacks and the approved mobile sizes retain their precedence.
Do not move a later declaration to an earlier file solely because its selector
appears there too.

## Editing rules

- Place feature changes in the relevant existing feature file and media block.
  Read later declarations of the same selector before changing specificity.
- Extend theme roles in `product-tokens.css` when a new shared color role is
  needed. Reuse the existing roles in features.
- Scope each question-bank selector to `.qb-*` or `#questionBankPageHost`.
  Shared element styles belong to the foundation and shared controls.
- Preserve fallback declaration order, `!important`, nested media/container
  conditions, reduced-motion/forced-colors behavior and complete print output.
- Do not use `@import`. Add a new source to its explicit bundle position. Keep
  a file below 1,200 lines by splitting at complete top-level rule boundaries
  when responsibilities grow.

## Verification

`audit/css-organization.test.cjs` verifies complete and unique source inclusion,
the two stylesheet load positions, independent parsing, bounded source sizes,
absence of runtime imports and question-bank selector isolation.

`audit/touch-css-redundancy.test.cjs` scans the entire ordered touch product
group after its split; it does not lose coverage at file boundaries.
`audit/css-compaction-browser.cjs`, included in the release workflow review,
compares every source CSSOM rule with the generated bundle in the native
browser, including font bytes, selector order, media/container queries,
keyframes, declarations and priorities. It reads the current manifest, so
intentional design changes do not require updating a frozen visual hash.

For this organization change, all eight extracted sources were compared with
their earlier ASTs, in full order. Both generated CSS files also retain exactly
the previous executable bytes; only source maps gain their new source paths.
