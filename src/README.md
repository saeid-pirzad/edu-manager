# کد منبع EduManager

کدهای قابل ویرایش برنامه در این پوشه‌اند. فایل‌های JavaScript و CSS در `assets/`
خروجی ساخت هستند؛ مستقیم ویرایش نشوند. `npm run build` آن‌ها را تولید می‌کند.

## مسیرها

| مسیر                | مسئولیت                                                                                   |
| ------------------- | ----------------------------------------------------------------------------------------- |
| `domain/`           | محاسبهٔ نمره، تقویم، CSV، رمز، پیش‌نویس و قواعد امن داده                                  |
| `data/`             | schema، اتصال IndexedDB، codec رکورد، برنامهٔ ذخیره و تراکنش اتمیک                        |
| `validation/`       | اعتبارسنجی پشتیبان کامل، کارنامهٔ ثابت و undo                                             |
| `services/`         | سرویس‌های مستقل نمرات، اکسل، snapshot و مجوز یادداشت؛ وابستگی‌ها از factory تزریق می‌شوند |
| `ui/`               | تقویم، پنجره‌ها، پوسته و فرم تنظیمات درس                                                  |
| `reports/periodic/` | بازهٔ تاریخ، یادداشت، مدل گزارش، متن، HTML، فیلتر و خروجی                                 |
| `pwa/`              | manifest و کنترل نصب/به‌روزرسانی                                                          |
| `styles/`           | استایل‌ها به تفکیک اجزا؛ فونت‌های آفلاین در `fonts.css`                                   |
| `legacy/`           | رابط سازگار موجود: صفحات، جلسات، برنامهٔ هفتگی، گزارش و ورود داده                         |
| `workspace/`        | دوره‌ها، state، ذخیره، پیش‌نویس، پشتیبان، تاریخچه و تنظیمات                               |

## قرارداد ساخت

`source-map.json` ترتیب فایل‌های هر خروجی را مشخص می‌کند. منابع `workspace/` اتصال
سرویس‌ها و گردش رابط را در scope خصوصی نگه می‌دارند؛ منابع `legacy/` API سازگار
classic مرورگر را حفظ می‌کنند. منطق نمرات، ساخت دادهٔ اکسل، snapshot پشتیبان و
مجوز یادداشت سالانه در `services/` factory مستقل دارند و از وضعیت workspace، DOM
یا storage به‌طور پنهان استفاده نمی‌کنند. `application-services.js` پیش از workspace
بارگذاری می‌شود. این ساختار به ES module یا سرویس شبکه نیاز ندارد.

وابستگی سرویس جدید باید در پارامتر factory صریح باشد. دادهٔ زنده از callback خوانده
شود و state متعلق به هر نمونه داخل همان factory بماند. `scripts/architecture-boundaries.cjs`
همراه lint و تست اجرا می‌شود؛ متغیر آزاد برنامه، state بیرون factory، API مرورگر
تزریق‌نشده و export اضافی را رد می‌کند. فایل‌های workspace چهار سرویس فقط adapter هستند؛
منطق محاسبه و cache در آن‌ها اضافه نشود.

فایل‌های `ui/course/` داخل factory تنظیمات درس و فایل‌های `reports/periodic/` داخل
scope گزارش دوره‌ای قرار می‌گیرند. استایل‌ها با حفظ ترتیب cascade ترکیب می‌شوند؛
نقشهٔ مسئولیت و قرارداد افزودن قواعد در [راهنمای CSS](styles/README.md) آمده است.

برای افزودن یک فایل، آن را در ترتیب مناسب `source-map.json` ثبت کنید. ساخت، فایل
منبع ثبت‌نشده، منبع تکراری یا خروجی نامعتبر را رد می‌کند. برای output جدید باید
ارجاع آن در HTML هم اضافه شود؛ cache و نسخهٔ PWA هنگام build محاسبه می‌شوند.

## چرخهٔ توسعه

1. فایل موضوعی مناسب را در `src/` تغییر دهید.
2. `npm run build` را اجرا کنید.
3. پس از `npm ci`، دستور `npm run check` را اجرا کنید؛ برای تست واحد تنها، `npm run test:unit` کافی است.
4. برای اجرای محلی `npm run dev` را اجرا کنید.

نام storeها، کلیدهای ذخیره، نسخهٔ schema و قرارداد backup به داده‌های قبلی وابسته‌اند.
تغییر آن‌ها نیازمند migration و تست سازگاری است. آزمون‌ها فقط دادهٔ ساختگی و پروفایل
مستقل مرورگر را به کار می‌برند.

رویدادهای قالب‌های قدیمی در `legacy/events/`، رویدادهای تقویم در `ui/events-calendar.js`
و رویدادهای گزارش در `reports/periodic/events-*.js` هستند. این‌ها کد منبع عادی و
قابل‌ویرایش‌اند؛ فایل‌های موقت مهاجرت حذف شده‌اند. کلیدهای data به توابع ثبت‌شده
اشاره می‌کنند؛ متن رویداد از HTML خوانده یا اجرا نمی‌شود. هنگام افزودن عملیات،
تست و قرارداد قفل ویرایش، فوکوس و صفحه‌کلید آن را نیز حفظ کنید.
