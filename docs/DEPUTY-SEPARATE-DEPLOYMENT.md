# نشانی مستقل کارتابل معاون

دبیر در GitHub Pages فعلی می‌ماند. خروجی معاون روی یک سایت Cloudflare Pages با
نام دامنهٔ متفاوت منتشر می‌شود. پروژه، مخزن و منطق برنامه یکی است؛ سرور داده یا
بک‌اند اضافه نمی‌شود. پوشه یا مخزن دوم زیر همان username.github.io جداسازی
فضای مرورگر ایجاد نمی‌کند.

## خروجی

`npm run build:deputy`

پوشهٔ `dist/deputy` فقط فایل‌های عمومی اجرای معاون را دارد؛ بانک اطلاعاتی،
فایل پشتیبان کاربر و اطلاعات دبیر در آن نیست. صفحهٔ اول، معاون را باز می‌کند و
manifest و کش آفلاین خروجی، مستقل از سایت دبیرند. از فایل‌های اصلی کپیِ قابل
ویرایش جدید ساخته نمی‌شود؛ خروجی همیشه از همین منبع ساخته می‌شود.

در ویندوز، همین فرمان فایل آمادهٔ بارگذاری
`dist/edu-manager-deputy.zip` را هم به‌روز می‌کند. در Cloudflare یا Linux فقط
پوشهٔ خروجی ساخته می‌شود. ورودی خروجی مستقل، `index.html` در ریشه است تا
تغییر نشانی خودکار فایل‌های HTML در Cloudflare، نصب و کش آفلاین را خراب نکند.

## راه‌اندازی ساده در Cloudflare

1. در حساب خود به Workers & Pages بروید و گزینهٔ ساخت Pages با Direct Upload یا
   Drag and drop را انتخاب کنید. نام گزینه‌ها ممکن است با تغییر پنل متفاوت شود.
2. نام پیشنهادی پروژه `edumanager-deputy-pirzad` است؛ آزاد بودن نام را Cloudflare
   تعیین می‌کند. نشانی نهایی همان نشانی pages.dev نمایش‌داده‌شده در پنل خواهد بود.
3. فقط پوشهٔ `dist/deputy` یا فایل ZIP محتوای آن را بارگذاری و Deploy کنید؛
   پوشهٔ کل پروژه، پوشهٔ audit یا هیچ فایل پشتیبان شخصی را ارسال نکنید.
4. نشانی نهایی را در مرورگر باز کنید. عنوان باید کارتابل معاون باشد. پس از پیام
   «آماده اجرای آفلاین» امکان اجرای آفلاین را بررسی کنید.
5. در معاونِ نشانی قدیمی، «پشتیبان و بازیابی ← دریافت پشتیبان کامل» را بزنید.
   فایل را در معاون نشانی جدید بازیابی کنید؛ تعداد پرونده‌ها و پیگیری‌ها را
   بررسی کنید و بعد برنامهٔ جدید را نصب کنید. دادهٔ قدیمی خودکار حذف نمی‌شود.
6. پس از تأیید مهاجرت، فقط از نشانی جدید معاون استفاده کنید؛ اطلاعات دو نشانی
   خودکار همگام نمی‌شوند. اتصال پشتیبان خودکار فایل را نیز در نشانی جدید دوباره
   انتخاب کنید، چون مجوز فایل قابل انتقال با JSON نیست.

Direct Upload به اتصال Git نیاز ندارد. برای انتشار اصلاحات بعدی، خروجی تازهٔ
همین فرمان را در همان پروژهٔ Cloudflare بارگذاری کنید. پروژهٔ Direct Upload
قابل تبدیل مستقیم به Git integration نیست؛ اگر از ابتدا انتشار خودکار از Git
می‌خواهید، به‌جای Direct Upload یک پروژهٔ Git-connected با همین مخزن بسازید:
Build command برابر `npm run build:deputy` و Output directory برابر
`dist/deputy`. پیش از ساخت از Git، تغییرات باید در مخزن ارسال شده باشند.

## مرز حفاظت

پاک‌کردن داده‌های **سایت معاون** روی اطلاعات **سایت دبیر** اثر ندارد و برعکس.
پاک‌کردن همهٔ اطلاعات مرورگر، حذف پروفایل، خرابی دستگاه یا انتخاب همان فایل
برای پشتیبان خودکار دو برنامه با جداسازی نشانی برطرف نمی‌شود؛ پشتیبان مستقل
هر کارتابل را نگه دارید.

## بررسی

- `node --test audit/deputy-deployment.test.cjs`: فهرست فایل‌های خروجی و حذف
  داده‌های ناخواسته، بازتولید یکسان خروجی و نسخه‌بندی کش.
- `node audit/deputy-origin-browser.cjs`: مرورگر موقت با دو مبدأ مجزا؛ مهاجرت
  پشتیبان شامل نمرهٔ صفر و پیگیری، نصب‌پذیری manifest، آفلاین و پاک‌سازی دادهٔ
  هر طرف بدون تغییر طرف دیگر. این آزمون به مرورگر یا دادهٔ واقعی کاربر دست نمی‌زند.
