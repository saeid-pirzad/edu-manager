# نتیجهٔ تفکیک منبع EduManager

در این بازسازی، کد اجرایی تک‌فایلی به درخت منبع موضوعی و خروجی ساخت قابل تکرار تبدیل شد.
مرجع ویرایش برنامه `src/` است؛ HTML فقط پوسته را نگه می‌دارد و فایل‌های `assets/`
برای انتشار تولید می‌شوند. فایل‌های خروجی بزرگ، bundle هستند و کد دست‌نویس مرجع محسوب نمی‌شوند.

## تفکیک انجام‌شده

- ۱۷۳ فایل منبع JavaScript/CSS.
- ۲۹ خروجی JavaScript/CSS با ترتیب ثبت‌شده در `source-map.json` و نگاشت دیباگ `.map` برای هر خروجی.
- تفکیک صفحات، نمره‌دهی، دانش‌آموزان، جلسات، برنامهٔ هفتگی، گزارش‌ها و ابزارهای رابط.
- تفکیک منبع دوره‌ها، پشتیبان، پیش‌نویس، تاریخچه، undo، تنظیمات و هم‌زمانی.
- ماژول‌های مستقل برای اتصال IDB، codec، تراکنش اتمیک، اعتبارسنج‌ها و محاسبات دامنه.
- تفکیک گزارش دوره‌ای و فرم درس در scopeهای خصوصی موجود.
- تقسیم استایل‌ها با حفظ cascade؛ فونت‌های آفلاین حفظ شده‌اند.
- تقسیم سناریوهای مرورگر در `audit/flows/` و حذف تزریق متن کد به runner.

## ابزار توسعه و کنترل انتشار

- `npm run build`: تولید خروجی، فهرست cache و شناسهٔ نسخه از محتوای کل انتشار.
- `npm run build:check`: رد خروجی قدیمی و منبع ثبت‌نشده، بدون تغییر فایل.
- `npm run dev`: سرور محلی روی loopback؛ فقط فایل‌های انتشار را سرو می‌کند.
- `npm test`: تست واحد، کنترل ساخت، قرارداد داده/asset و تست کامل مرورگر/PWA.
- `npm run check`: قالب‌بندی، ESLint، ساخت و کل تست‌ها؛ همان دستور CI پس از `npm ci`.
- `npm run bench`: سنجش مستقل برنامهٔ ذخیره با دادهٔ ساختگی تا ۵۰۰۰۰ رکورد.
- بدون dependency خارجی برای build یا تست واحد؛ مرورگر Edge برای تست یکپارچه لازم است.

## صحت و حدود تغییر

اجرای نهایی `npm run check`: قالب‌بندی، ESLint، ۸۱ تست واحد و ۳۰۴ تست مرورگر موفق، صفر شکست.
دو آزمون نگاشت منبع، خطوط خروجی و گذار بین فایل‌ها را نیز بررسی می‌کنند.
`npm run build:check` همگامی ۲۹ خروجی با ۱۷۳ فایل منبع را بررسی می‌کند.
سرور محلی برای HTML/CSS/JavaScript و عدم انتشار مسیرهای منبع بررسی شد.

عملیات داده و schema کاربران حفظ شده‌اند. پیش‌نویس نامعتبر در backup جدا می‌ماند؛
کارنامهٔ قدیمی بدون مؤلفهٔ ساختگی خوانده می‌شود. تعارض revision، undo و restore
همچنان در تراکنش‌های واقعی آزمایش می‌شوند. محتوای CSS با همان ترتیب به خروجی می‌رود.

منابع legacy و workspace هنوز bindingهای مشترک سازگار دارند و با ترتیب manifest
ترکیب می‌شوند؛ این کار مهاجرت به framework جدید یا تبدیل سراسری به ES module نیست.
handlerهای اجرایی inline از منبع حذف شده‌اند و CSP اجرای آن‌ها را مسدود می‌کند. تست دستگاه واقعی Android/iPhone
و ممیزی یک بازنویسی مستقل در پوشه‌ای دیگر، خارج از این نتیجه‌اند.

## اصلاحات ممیزی تکمیلی

- شناسهٔ انتشار نسبت به LF/CRLF پایدار است و تغییر منطق خود service worker را هم پوشش می‌دهد؛ هر دو تست بازگشت دارند.
- بازنویسی ۴۸ تابع عمومی در زمان اجرا با facade ثابت و ثبت یک‌بارهٔ پیاده‌سازی جایگزین شد؛ مسیرهای قدیمی fallback مشخص دارند.
- نگاشت استاندارد source map نسخهٔ ۳ برای JavaScript/CSS تولید، سرو و cache می‌شود؛ محتوای منبع در آن عمومی است و نباید راز در کد قرار گیرد.
- گردش CI برای اجرای تست روی Windows/Node 22 اضافه شد؛ اجرای آن در GitHub هنوز انجام نشده است.
- مشکل نصب ابزارها رفع شد: Prettier و ESLint نصب، نسخه‌ها قفل و قالب‌بندی سراسری و lint اجرا شدند. فایل ممیزی مربوط به بازنویسی خارج از دامنه، خروجی‌های ساخت و service worker تولیدی از قالب‌بندی مستقیم مستثنی‌اند.
- handlerهای inline پوسته و فرم ورود حذف شدند؛ رویدادهای بستن modal، واردکردن JSON/CSV و submit ورود اتصال صریح دارند. سه آزمون مستقل برای اتصال، dispatch و render مجدد اضافه شد.
- هشت عملیات header به actionهای صریح و event delegation منتقل شدند؛ selector تنظیمات موبایل و بازگشت فوکوس modal با قرارداد جدید هماهنگ شدند. سه تست واحد و شش سناریوی مرورگری برای این بخش اضافه شد.
- تست مرورگری، افت فوکوس بر اثر چیدمان زمان‌بندی‌شدهٔ پوسته پس از بسته‌شدن modal را آشکار کرد؛ زمان بازیابی فوکوس و مقصد قابل‌دیدن منوی موبایل اصلاح شدند.
- رویدادهای submit و انصراف فرم تنظیمات از HTML جدا و به همان نمونهٔ فرم متصل شدند؛ دو تست واحد برای اتصال/امتناع modal و دو تست مرورگری برای ذخیرهٔ بدون تغییر و انصراف فرم بازشدهٔ مجدد اضافه شدند.
- رویدادهای فرم درس (ذخیره، شاخه، روش و انصراف) به `form-events.js` منتقل شدند؛ دو تست واحد اتصال/خطای غیرهم‌زمان و پنج سناریوی مرورگری قالب، تغییر روش، اعتبارسنجی و انصراف اضافه شدند.
- رویداد معیارهای الزامی جدول نمرات از inline به listener خصوصی پایدار منتقل شد؛ شناسه‌ها escape می‌شوند. سه تست واحد و چهار بررسی مرورگری برای اتصال و ذخیرهٔ سه وضعیت اضافه شدند. این مرحله پایهٔ مهاجرت سراسری بعدی شد.
- رویدادهای gradeCell شامل input، خروج از فیلد و پاک‌کردن به listenerهای پایدار منتقل شدند؛ شناسه‌های قالب escape می‌شوند. سه تست واحد و چهار سناریوی مرورگری برای اعتبارسنجی، اصلاح، ذخیره و پاک‌کردن اضافه شدند.
- رویدادهای فرم اصلاح عنوان نوبت از HTML جدا شدند؛ context قبلی در صورت رد جایگزینی modal حفظ می‌شود. دو تست واحد و چهار سناریوی مرورگری برای اتصال، اعتبارسنجی، ذخیرهٔ بدون تغییر و انصراف اضافه شدند.
- دو snapshot قدیمی نتایج آزمون از درخت کاری حذف و ارجاع‌هایشان اصلاح شدند؛ نسخه‌های تاریخی در Git قابل بازیابی‌اند. snapshotهای بعدی در مخزن ثبت نمی‌شوند. فایل موقت یا asset خارج از manifest ساخت شناسایی نشد؛ منبع، تست و خروجی‌های ضروری حفظ شدند.

## تکمیل کنترل کیفیت — ۲۰۲۶/۱۰/۲۶

- ESLint دو نقص واقعی را آشکار کرد: متغیر هشدار مهاجرت تعریف نشده بود و تعریف دوبارهٔ showModal، facade ثابت را دور می‌زد. هر دو با تست بازگشت اصلاح شدند؛ علت خطاهای تبدیل‌شده نیز با `cause` حفظ می‌شود.
- کل workspace، رابط legacy، تقویم و گزارش‌های دوره‌ای از handler اجرایی inline پاک شدند. توابع در فایل‌های مسئولیت‌محور ثبت می‌شوند و پارامترها از data attributeهای escape‌شده خوانده می‌شوند؛ eval یا Function constructor استفاده نمی‌شود. ابزارهای موقت مهاجرت پس از استفاده حذف شدند.
- quirk مربوط به bubbling، کلیدهای صفحه‌کلید، برچسب فیلترها، قفل کنترل‌های دورهٔ بسته و مقصد فوکوس با قرارداد رویداد جدید هماهنگ شدند. تست منبع، بازگشت handlerهای inline را رد می‌کند.
- معیار پودمان پیش از ایجاد داده، مقدار را اعتبارسنجی می‌کند و پس از انتظار برای پیش‌نویس‌ها، تغییر دوره یا کلاس را رد می‌کند.
- پنجرهٔ نمرات گروهی، پشتیبان‌ها و فهرست دوره‌ها محافظ مشترک مقصد غیرهم‌زمان دارند. پنج تست واحد و دو تست مرورگری، از جمله تعویض واقعی دوره هنگام تأخیر برآورد فضای پشتیبان، موفق شدند. شاخهٔ تکراری و غیرقابل‌دسترسی نمرات کاردانش نیز حذف شد.
- چهار آزمون نمایش نام‌های مخرب و یک آزمون واقعی مسدودشدن handler تزریقی توسط CSP موفق‌اند. بازشدن مستقیم HTML محلی با file: نیز در profile ایزولهٔ Edge موفق بود.
- `npm ci --offline --ignore-scripts` نصب تکرارپذیر lockfile را تأیید کرد. `npm audit --json` در این تاریخ برای وابستگی‌های نصب‌شده، صفر آسیب‌پذیری شناخته‌شده گزارش کرد؛ این نتیجه تضمین امنیت جامع یا آینده نیست.

## کارایی اندازه‌گیری‌شده

در اجرای محلی Node 22.23.2، میانهٔ برنامه‌ریزی ذخیره برای ۵۰۰۰۰ رکورد حدود ۹۸ میلی‌ثانیه
در حالت بدون تغییر و ۱۲۶ میلی‌ثانیه برای تغییر یک رکورد بود. این سنجش فقط حافظه/برنامهٔ
ذخیره است، نه سرعت دیسک یا IndexedDB.

در Edge ایزوله، جدول یک پودمان برای ۱۰۰/۵۰۰/۱۰۰۰ هنرجو با ۲۰۰/۱۰۰۰/۲۰۰۰ ورودی
نمره ساخته شد. زمان نصب و بهبود چیدمان تقریباً ۱۷۲/۶۲۷/۱۲۰۴ میلی‌ثانیه بود؛ هر سه
بدون تغییر دادهٔ ذخیره‌شده موفق بودند. این اعداد وابسته به دستگاه و وضعیت سیستم‌اند،
بودجهٔ تضمین‌شدهٔ گوشی نیستند و جدول همهٔ پودمان‌ها یا کل بانک بزرگ را پوشش نمی‌دهند.

## پذیرش‌هایی که در این محیط ممکن نیست

دسترسی به Android واقعی، iPhone/Safari و حساب انتشار فراهم نشده است؛ آن‌ها تأیید نشده‌اند.
برای هر دستگاه، نصب اولیه و اجرای آفلاین پس از بستن برنامه، به‌روزرسانی، صفحه‌کلید فارسی
و اعشار نمره، تقویم و بازگشت فوکوس، دانلود JSON/TXT و بازیابی فایل ساختگی باید ثبت شوند.
CI فقط تعریف شده و اجرای آن روی GitHub یا انتشار نسخه در این کار انجام نشده است.
همچنین معماری classic با scope مشترک، آگاهانه حفظ شده؛ تبدیل کامل به ES module و
تست نفوذ مستقل، ادعا یا انجام نشده‌اند.

راهنمای ساختار: `src/README.md`، راهنمای آزمون: `audit/README.md`، قرارداد معماری:
`docs/ARCHITECTURE.md`. نتیجهٔ هر اجرای تازه از مسیر `resultFile` چاپ‌شده در تست قابل بررسی است.
