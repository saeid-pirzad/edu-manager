## تصمیم‌های حفظ داده

- مدل ذخیره و شناسه‌های قبلی به‌زور به یک رکورد بزرگ تبدیل نشدند؛ یکپارچگی محصول با مرز سال و تراکنش مشترک پیاده شد تا نمره و ارجاع تاریخی از بین نرود.
- اصلاح تعریف و هویت مشترک، جلسات واقعی یا کارنامهٔ ثابت قبلی را جعل نمی‌کند. نام‌های موقتِ علامت‌خورده مسیر ترمیم مشخص دارند.
- بازیابی عمومی ادغام نیست. اطلاعات عملیاتی نصب قبلی پاک و محتوای فایل جایگزین می‌شود؛ نسخهٔ ایمنی وضعیت قبل عمداً در برنامه باقی می‌ماند.
- گزارش سالِ ناقص مجاز است؛ نمرهٔ مفقود صفر نمی‌شود و نتیجهٔ نهایی بدون چهار مرحله کامل ساخته نمی‌شود.
- در تعارض واقعی قدیمی، overwrite حدسی انجام نمی‌شود. فایل و سابقه حفظ و تصمیم لازم آشکار می‌شود.

## حدود نتیجه

آزمون مرورگر، Edge رومیزی با viewportهای موبایل است؛ نصب و رفتار فایل/اشتراک‌گذاری روی Safari واقعی iPhone و Chrome واقعی Android همچنان آزمون دستگاه می‌خواهد. موفقیت این ممیزی ادعای نبود مطلق باگ نیست.

رمز ورود رمزگذاری نیست؛ فایل JSON حاوی دادهٔ خوانا است. برنامه backend و همگام‌سازی بین دستگاه ندارد. محدودیت اجرای پس‌زمینه و مجوز فایل متعلق به مرورگر است؛ این پروژه نمی‌تواند هنگام بسته‌بودن برنامه روی همهٔ دستگاه‌ها فایل خارجی را زمان‌بندی و بازنویسی کند.

سال‌ها یا نوبت‌های مبهمِ فایل قدیمی خودکار پاک نمی‌شوند. محدودیت حافظهٔ دستگاه برای فایل بسیار بزرگ همچنان واقعی است. بازیابی باید از فایل معتبر انجام شود و خطا، نسخهٔ سالم قبلی را از بین نبرد.

## بازگشت به تصمیم‌های صریح کاربر، بدون تغییر استایل — ۲۰۲۶/۱۱/۰۲

مبنای این مرحله، مخزن `D:/2-Projects/02-1405/edu-manager` و commit آغازین `5b18b38` است. درخواست کاربر، اصلاح منطق و آزمون‌ها با حفظ UI تأییدشده بود. دو انتخاب صریح مرجع قرار گرفتند: «فقط یک سال، بدون مدیریت سال‌های دیگر» و «گزارش روزانه/هفتگی/ماهانه فقط ترم انتخاب‌شده، با عنوان روشن». ادعای آزمون موفق نسخه‌های قدیمی به نسخهٔ آغازین این مرحله تعمیم داده نشد.

### اصلاح‌های تأییدشده

1. **وابستگی واقعی آزمون حضور:** در اجرای آغازین، ۱۲۵۴ از ۱۲۵۵ آزمون موفق و آزمون فهرست جلسات با `EduIcons is not defined` ناموفق بود. آزمون اکنون ماژول واقعی آیکن را پیش از جدول بارگذاری می‌کند؛ هیچ assertion حذف یا جایگزین با نتیجهٔ ثابت نشد. هم وجود SVG و هم شمارش درست تأخیر در حاضر کنترل می‌شود.
2. **محدودهٔ واقعی گزارش:** درخواست همیشگی `yearWide: true` حذف شد. گزارش روز، هفته و ماه از snapshot پایدار ترم فعال می‌آید؛ عنوان، آمار، جلسات و فعالیت، JSON، متن، کپی معاون و چاپ یک محدوده دارند. گزارش خالی نیز نام ترم را نگه می‌دارد. گزارش سالانه همچنان هر دو ترم همان سال را می‌خواند و سالِ فقط دارای ترم اول قابل گزارش است.
3. **کارنامهٔ سالانهٔ اولیا:** جدول موجود حفظ شد؛ منبع سالانهٔ نمره با snapshot جدا تهیه می‌شود، بدون گسترش دامنهٔ جلسات ترم انتخاب‌شده. شناسه و revision منبع جاری باید منطبق باشند و پیش از نمایش و تحویل، guard هر دو منبع کنترل می‌شود. `periods` در JSON محدودهٔ جلسات و `gradePeriods` محدودهٔ نمرات سالانه را صریح نشان می‌دهند. نمرات پودمانی سالانه باقی ماندند.
4. **تفکیک توضیحات:** یادداشت روز/هفته/ماه به ترم فعال تعلق دارد؛ یادداشت سالانه مشترک سال است. یادداشت‌های قدیمی، از جمله کلیدهای سالانهٔ ایجادشده برای گزارش غیرسالانه، حذف نشدند و در خروجی کامل باقی‌اند؛ متن مبهم به ترم دیگر نسبت داده نمی‌شود. پاک‌کردن صریح یادداشت سالانه و عدم برگشت خودکار متن قدیمی همچنان آزموده می‌شوند.
5. **فقط یک سال:** ساخت و انتخاب سال دیگر از hub، dispatcher و API عمومی حذف شد. جابه‌جایی عمومی پیش از همگام‌سازی مقصد، سال را کنترل می‌کند و گزینهٔ تزریق‌شده مجوز نمی‌سازد. دادهٔ تاریخی چندساله در بانک، پشتیبان و بازیابی محفوظ است؛ سال فعال فایل بازیابی‌شده و انتخاب پایدار پس از reload حفظ می‌شوند. مسیر fixture چندساله با capability خصوصی و بررسی صریح حالت آزمون از API عادی جداست. چهار مرحلهٔ نمره و ثبت مرحلهٔ دوم بدون بستن اول، تغییری نکردند.
6. **وضعیت صحیح ذخیرهٔ نمره:** با ورودی نظری نامعتبر و عملی معتبر، ثبت مقدار معتبر باعث می‌شد پیام نظری به «ذخیره شد» تبدیل شود؛ در حالی که مقدار نامعتبر هنوز پیش‌نویس بود. این ایراد قبل از اصلاح بازتولید شد. refresh اکنون منبع پیش‌نویس همان زمینهٔ ارزشیابی را می‌خواند؛ `aria-invalid`، وضعیت هر کادر و ردیف، صفر، مقدار خالی، پاک‌کردن صریح، ورودی تازه حین commit، رندر مجدد و هنرجویان مختلف درست تفکیک می‌شوند. پیام دادهٔ منقضی، مسیر امن بارگذاری مجدد و بررسی پیش‌نویس محفوظ را بیان می‌کند؛ قفل و کنترل نسخه دور زده نمی‌شوند.

سناریوی جدید `assessment-status-browser.cjs` با فرم واقعی و IndexedDB در profile ساختگی، هر دو ترم، صفر در کنار نمرهٔ نامعتبر، منع گزارش تا اصلاح، پاک‌کردن، اصلاح مجدد و حفظ workspace فعال را کنترل می‌کند؛ نصب اولیه در پایان برگردانده می‌شود. سناریوی سال نیز نبود مسیر چندساله، رد گزینهٔ جعلی، حفظ سوابق قدیمی و بازیابی/reload را از کنترل‌های واقعی بررسی می‌کند. fixtureهای قدیمی فقط برای آماده‌سازی دادهٔ تاریخی به API آزمون منتقل شدند؛ جابه‌جایی واقعی بین دو ترم همان سال همچنان از API عمومی آزموده می‌شود.

CSS منبع و خروجی، رنگ‌ها، فاصله‌ها، فایل HTML اصلی و `docs/School-doc` تغییر نکردند. تغییر رابط صرفاً حذف کنترل قابلیت چندسالهٔ مغایر قرارداد و تصحیح متن/وضعیت منطقی است، نه بازطراحی. فایل خالی و بدون ارجاع `{console.error(error.stack)` از ریشه حذف شد؛ محتوایی نداشت و نسخهٔ ثبت‌شدهٔ آن در Git موجود است.
