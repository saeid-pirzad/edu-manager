## محدودیت دو مرحلهٔ حذف

حذف فایل دستگاه و تراکنش IndexedDB یک تراکنش مشترک ندارند. ابتدا فایلِ اعتبارسنجی‌شده حذف می‌شود و سپس دادهٔ همان بخش پاک می‌شود. اگر مرحلهٔ دوم شکست بخورد، فایل ممکن است حذف شده باشد و اطلاعات برنامه باقی بماند. این حالت پیام صریح دارد و نوشتن خودکار فایل حذف‌شده از سر گرفته نمی‌شود. فایل پشتیبان مستقل برای بازیابی لازم است.

برای فایل متصل با نام قدیمی یا نام خارج از قرارداد، حذف متوقف می‌شود. راه خروج، بررسی و قطع اتصال همان بخش و مدیریت دستی فایل مشخص در دستگاه است؛ سپس حذف دادهٔ برنامه با پیش‌نمایشِ بدون فایل قابل انجام است. کنترل نام برای دورزدن خطا برداشته نشده است.

## اعتبارسنجی

- ۱۳۱ آزمون مرتبط با نام، حذف، تراکنش، زمینهٔ عملیات و بازیابی پس از شکست: موفق، صفر شکست. شامل هشت مورد جدید در این تغییر.
- ۱۳۶ آزمون نام و ذخیرهٔ فایل مدرسه برای بررسی اثر جانبی: موفق، صفر شکست. آزمون‌های نام با اجرای قبلی هم‌پوشانی دارند.
- ۳۰۵ بررسی در مرورگر ایزولهٔ مرکز پشتیبان: موفق، صفر شکست. حذف واقعی فایل مصنوعی مدرسه و بانک، حفظ بخش مقابل، انصراف و دیالوگ در عرض‌های موبایل تا دسکتاپ را شامل می‌شود. شمار کل شامل بررسی‌های مشترک runner است.
- build، lint و کنترل همگامی خروجی: موفق.

فرمان‌های مرتبط:

```powershell
node --test audit/wipe-recovery.test.cjs audit/qb-clear.test.cjs audit/question-bank-file-backup.test.cjs audit/single-file-name.test.cjs audit/deletion-context.test.cjs
node --test audit/single-file.test.cjs audit/single-file-name.test.cjs
node audit/unified-backup-hub-browser.cjs
npm run lint
```

این اجرا پذیرش روی دستگاه فیزیکی یا اجرای مجدد تمام دروازهٔ انتشار نیست. هیچ اطلاعات واقعی یا فایل انتخابی کاربر حذف نشد.
